# FilePhile PWA Setup

## Overview
FilePhile is now configured as a fully functional Progressive Web App (PWA) with iOS installation support.

## What Was Done

### 1. Created PWA Manifest (`manifest.webmanifest`)
- Proper app metadata (name, description, theme colors)
- Icon references at multiple sizes (72px to 512px)
- Standalone display mode for app-like experience
- Flexible orientation (adapts to device)
- Official FilePhile SVG icon support

### 2. Official FilePhile Icons
The actual icon set (generated by `scripts/generate-icons.mjs`):
- `FilePhile-official.svg` - Vector icon for scalability (source of truth)
- `apple-touch-icon.png` (180×180) - iOS home screen; transparent glyph at ~80% fill
- `icon-{72,144,192,384,512}.png` - Android, PWA, and Windows tiles; transparent glyph at ~90% fill
- `icon-512-maskable.png` - Android adaptive icon; glyph inside the ~80% safe zone
- `favicon.ico` (repo root) - multi-size 16+32+48 px, PNG-compressed entries
- Windows tile support via `browserconfig.xml`

#### Regenerating icons

```bash
npm install playwright-core   # once; a system Chromium is enough
node scripts/generate-icons.mjs [--exe=/path/to/chromium]
```

The script renders the SVG centered on a square canvas (the source viewBox is a
non-square 974×925), writes every raster asset, assembles `favicon.ico` in pure
Node (ICO with embedded PNGs — no ImageMagick needed), and prints a self-check
table (corner transparency + glyph coverage). After regenerating, bump the
`?v=` cache-busters in `index.html`, `manifest.webmanifest`, `sw.js`, and
`browserconfig.xml`, and bump the Service Worker `CACHE_NAME`.

#### iOS icon behavior (important)

All icons ship with **transparent backgrounds** (deliberate product decision).
iOS 18+ composites transparent web-clip icons onto a system backplate that
follows the icon appearance setting (white in light mode, dark in dark/tinted
mode). Two caveats:
- iOS **caches the home-screen icon per install** — after deploying new icons,
  remove and re-add the web clip to see the change.
- On iOS 17 and earlier, transparency renders as a black background. If that
  matters for your audience, generate an opaque variant (adjust the script).
- A transparent `purpose: maskable` icon is off-spec on Android; some launchers
  may backfill black. Revisit if Android rendering disappoints.

### 3. Implemented Service Worker (`sw.js`)
- Caches essential app files for offline access
- Provides cache-first strategy with network fallback
- Enables app installation and offline functionality
- Auto-updates when new versions are deployed

### 4. Updated HTML
- Replaced inline data URI icons with proper file references
- Added service worker registration
- Maintained all iOS-specific meta tags:
  - `apple-mobile-web-app-capable`
  - `apple-mobile-web-app-status-bar-style`
  - `apple-mobile-web-app-title`

## iOS Installation Instructions

### For iPhone/iPad Users:

1. **Open in Safari** (required for iOS PWA installation)
   - Navigate to your FilePhile URL

2. **Tap the Share button** (square with arrow pointing up)
   - Located at the bottom of Safari (iPhone) or top (iPad)

3. **Scroll down and tap "Add to Home Screen"**
   - You'll see the FilePhile icon and name

4. **Tap "Add" in the top right**
   - The app will be added to your home screen

5. **Launch from Home Screen**
   - Tap the FilePhile icon
   - App opens in standalone mode (no browser UI)
   - Works offline after first load

### PWA Requirements Met:

- ✅ Service worker registered

- ✅ Multiple icon sizes
- ✅ Responsive design
- ✅ iOS-specific meta tags

### Icon Specifications:
All icons follow PWA and iOS best practices with official FilePhile branding:
- 180x180: iOS home screen (required)
- 192x192: Android, Chrome, general PWA
- 512x512: High-res displays, splash screens (plus a maskable variant)
- 72/144/384: Windows tiles and various contexts

### Service Worker Strategy:
- **Cache-first** for all requests with network fallback
- Serves cached content immediately when available
- Falls back to network if not in cache, then caches the response
- Automatic cache cleanup on version updates

## Troubleshooting

### Icon not showing on iOS
- Ensure `icons/apple-touch-icon.png` is accessible
- Check file is correctly sized (180x180 pixels)
- Verify all icon references in `index.html` point to `/icons/` directory
- Clear Safari cache and re-add to home screen

### Service Worker not registering
- Must be served over HTTPS (or localhost)
- Check browser console for errors
- Verify `sw.js` is in root directory

### App not installing
- Check all PWA requirements are met using Lighthouse
- Verify `manifest.webmanifest` is valid JSON
- Ensure icons are accessible and correct sizes
- Check that service worker is registered successfully
